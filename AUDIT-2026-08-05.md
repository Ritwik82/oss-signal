## 1. Code Quality Issues (file:line, severity-ranked)

### HIGH

**H1. Lint fails — 6 errors, 16 warnings** (`npm run lint`, exit 1)
- `src/components/daily-briefing.tsx:26` — `setMounted(true)` in effect (hydration guard — legitimately flagged; see fix)
- `src/components/fresh-finds.tsx:170` — `setIsNew(...)` in effect (pure derived state)
- `src/components/project-grid.tsx:216` — `setPage(0)` in effect (derivable in render)
- `src/components/relative-time.tsx:22` — `setLabel(...)` in effect (ticker pattern; needs `useSyncExternalStore` or lazy-init)
- `src/components/watchlist-panel.tsx:49,209` — `GenreChip`/`AppCard` **defined inside render** (component identity resets each render → state/focus loss risk)
- Warnings: unused vars in `scripts/refresh-data.mjs` (9), `scripts/verify-ui.mjs:18`, `scripts/check-live.mjs:5`, `src/app/page.tsx:5` (`GenreId`), `src/components/fresh-finds.tsx:6,12` (`abandonColor`/`abandonLabel`), `src/components/watchlist-panel.tsx:25` (`setStalenessFilter`)

**H2. `/api/updates` — unbounded server-side GitHub fan-out** (`src/app/api/updates/route.ts:56-69`)
`?repos=` splits on comma with **no cap on count** — each repo is one GitHub API call. An attacker sends one request with 1000 repos → 1000 upstream calls → burns GitHub's **unauthenticated 60/hr rate limit** in a single request, DoS-ing the app's own quota (this route is on the public Vercel domain, per the userscript). Regex validates format, not cardinality.

**H3. Half-wired filter state** (`src/components/watchlist-panel.tsx:25,30`)
`stalenessFilter` + `setStalenessFilter` exist; the filter is applied but **no UI ever sets it** — dead logic with an unused setter. Either wire a staleness filter chip row or delete the state.

**H4. Supply chain — 4 high-severity vulnerabilities** (`npm audit`, exit 1)
- `next@16.2.10` (production) — Middleware/Proxy bypass in App Router + Turbopack (GHSA-6gpp-xcg3-4w24); DoS in Server Actions (GHSA-m99w-x7hq-7vfj); SSRF in Server Actions on custom servers (GHSA-89xv-2m56-2m9x); cache-confusion of response bodies (GHSA-68g3-v927-f742, GHSA-4633-3j49-mh5q); unbounded Server Action payload (GHSA-4c39-4ccg-62r3); SSRF via rewrites (GHSA-p9j2-gv94-2wf4); DoS in Image Optimization with SVGs (GHSA-q8wf-6r8g-63ch); disclosure of internal server function endpoints (GHSA-955p-x3mx-jcvp). Fix: `next@16.3.0` — **outside the declared `^16.2.10` range**, needs a deliberate range bump. App uses no Server Actions, rewrites, or middleware today, which mitigates most of these — but the endpoint-disclosure and SVG-image DoS advisories should still be closed by upgrading.
- `postcss ≤8.5.22` (via next + tailwind) — XSS via unescaped `</style>` (GHSA-qx2v-qp2m-jg93); arbitrary file read via sourceMappingURL (GHSA-6g55-p6wh-862q, GHSA-r28c-9q8g-f849, GHSA-fxqj-rqcc-2cmp). Fix via next upgrade.
- `sharp <0.35.0` (via next) — libvips CVEs CVE-2026-33327/33328/35590/35591 (GHSA-f88m-g3jw-g9cj).
- `brace-expansion` (devDeps, eslint/typescript-eslint chain) — DoS via unbounded expansion (GHSA-mh99-v99m-4gvg, GHSA-rgw5-rvv9-x895) — dev-only, low practical risk, fixed by `npm audit fix`.

### MEDIUM

**M1. Dead code from the pivot (~600 lines):** `src/components/featured-section.tsx` (238 lines, `FeaturedSection` never imported anywhere), `createGenreClassifier` in `src/lib/data.ts:124` (exported, zero callers), `scripts/refresh-data.mjs:14-35,62,207,235` (7 unused constants/helpers incl. `BLOCKED_REPOS`, `MIN_STARS` — dead blocklist enforcement), `searchFetch` (62, superseded by `retryFetch`).

**M2. Section numbering collision** — `src/components/scoring-section.tsx:97` says `Section 02 / Methodology` but the left-rail numerals (I–IV) and siblings make it **Section 04**. (`featured-section.tsx:185` says "Section 03 / Specimen Gallery" — would collide with archive's 03, but it's dead code anyway.)

**M3. Wrong staleness semantics in color mapping** (`src/components/watchlist-panel.tsx:10`)
`case "warning": return "var(--color-accent)"` — warnings render in the **teal brand accent**, the same color used for active/healthy/interactive elements everywhere. A warning dot is visually indistinguishable from the brand's "everything is fine" color.

**M4. CSV formula injection** (`src/components/export-buttons.tsx:22-58`)
`watchlistCsv` escapes quotes/commas but not cells starting with `=`, `+`, `-`, `@` — a repo named `=HYPERLINK(...)` would execute as a formula when opened in Excel (CWE-1236). Names come from untrusted third-party GitHub repos.

**M5. `aria-expanded` mismatch in nav search** (`src/components/nav-bar.tsx:189`)
Listbox renders when `focused && query.trim()`, but `aria-expanded={focused && results.length > 0}` — with zero results the listbox is *visible* ("No matches for …") while `aria-expanded=false`. Also missing `aria-controls` (lint-flagged) and arrow-key navigation (incomplete ARIA combobox pattern).

**M6. No automated tests wired** — `@playwright/test` + `@axe-core/playwright` are devDeps and `scripts/*.mjs` exist, but there's **no `test` script** and zero test files. Your own AGENTS.md mandates TDD for logic bugs; `npm test` doesn't even exist.

**M7. `newSinceVisit` measures the wrong timestamp** (`src/components/daily-briefing.tsx:37-40`)
Compares `p.created_at` (GitHub **repo creation**) against last visit, but the catalog entry date is F-Droid `added`. A repo created 6 months ago but added to F-Droid yesterday is a fresh find that will never count as "new since your last visit."

- **L2.** `scripts/refresh-data.mjs:362` — two statements on one line (`const abandonmentRisk = ...; const last_release_at = ...`), formatting drift.
- **L3.** `src/components/fresh-finds.tsx:18` vs `src/components/project-grid.tsx:72` — `daysSince` duplicated (DRY).

## 2. UI/UX Assessment (visual + accessibility)

### Verified good (evidence above)
- **axe clean on both themes** (WCAG 2.1 A/AA, home + project pages), keyboard skip-link lands first and focus outlines are `solid 2px`
- Modal: real focus trap + return-focus, `aria-modal`, labelled, Escape + backdrop close, body scroll lock

- Thematic consistency is strong: calibration-marks, corner ticks, specimen numbering, mono micro-labels — a coherent, recognizable art direction

### HIGH-priority UX findings

**UX1. Pink still ships where you asked for amber** (refine decision from the Open Design session)
- `src/components/watchlist-panel.tsx:12` — `abandoned` → `--color-signal-pink` (#f472b6)
- `src/components/watchlist-panel.tsx:230` — "Needs attention" header → `--terracotta` (#ff2d95)
- `src/app/globals.css:33,41` — `--color-signal-red` and `--terracotta` are both magenta
- `src/app/globals.css:103` — the `.aurora` background has a pink radial `rgba(255,45,149,0.11)`
- `src/components/scoring-section.tsx:56` + `src/app/project/[...id]/page.tsx:11` — License signal dot is `signal-dot-pink`

Every state the refine message said should be warm amber (#ff9f43) — warnings, abandoned, alerts — is still pink on the live site. The generated dashboard prototype is amber; the real app is not. **Recommended mapping:** `abandoned` → `#ff9f43` (or `oklch(0.72 0.17 55)`), `--terracotta` → amber, `--color-signal-red` → true red (`#ff5d5d`), keep pink only for the License signal or drop it.

**UX2. Microtype legibility** — pervasive `text-[8px]`/`text-[9px]`/`text-[10px]` mono uppercase with `tracking-[0.2em]` (`nav-bar.tsx:129`, `watchlist-panel.tsx:82-83,89,98`, `fresh-finds.tsx:193`, `project-grid.tsx:109`). Passes contrast rules but is at the edge of human legibility on mobile displays. Bump the floor to 10px for decorative labels and 11-12px for any label that carries meaning (staleness, update badges).

**UX3. No search on mobile** — the nav search is `hidden sm:block` (`nav-bar.tsx:164`) and the mobile drawer only lists 4 section links. The archive search box exists but requires expanding the (collapsed by default) archive. Users on phones have no first-class way to find a specific app.

**UX4. Warning == brand color** (same as M3 — listed here because it's a UX bug first): teal warning dots read as "active/good."

**UX5. Light mode theme-color meta** (`src/app/layout.tsx:68`) is hardcoded `#1a1714` — in light mode the mobile browser chrome stays dark brown, clashing with `#fafafa` content.

### MEDIUM UX findings
- **UX6.** Combobox keyboard: results are tab-reachable links (passable), but no arrow-key roving / `aria-activedescendant` — the pattern is half-implemented.
- **UX7.** `FilterChip` uses `role="checkbox"` on `<button>` — the correct toggle semantics are `aria-pressed`; keyboard works either way but screen-reader announcement is off.
- **UX8.** `scroll-smooth` on `<html>` (`layout.tsx:65`) is not disabled under `prefers-reduced-motion` — anchor jumps still animate for motion-sensitive users (WCAG 2.3.3 boundary case).
- **UX9.** No `og:image`/`twitter:image` in metadata (`layout.tsx:24-46`) — link unfurls are text-only.
- **UX10.** Genre data quality: 91/744 (12%) of catalog entries classify to "other" — the substring classifier (`data.ts:124-141`, `refresh-data.mjs:219-229`) may be under-serving; worth a `classify-only.mjs` review run (AGENTS.md pattern).
